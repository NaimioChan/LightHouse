## 4. 判题手段对照

| 方向 | 断言读什么 | 关键手段 | 已知坑 |
|---|---|---|---|
| CSS | 计算值、几何、结构 | `getComputedStyle`、`getBoundingClientRect`、元素计数、`document.styleSheets` | 断言里的颜色要按实际计算值写；`<style>` 里用 Tailwind 时颜色是 `oklch(...)` 不是 `rgb(...)` |
| CSS 响应式 | 同一份代码在不同 iframe 宽度下的计算值 | 父页面改 iframe 宽度 → iframe 内视口变化 → 媒体查询与容器查询即时重估 | 需要判题内核支持"改宽度后重读一次"两阶段断言 |
| Vue | `nextTick` 之后的 DOM | 挂载后读 DOM、派发事件、再 `nextTick` 读 DOM | 现有 40 ms 静默期不够，判题要等 `nextTick` 或下一帧 |
| Vue SFC | DOM + `data-v-*` 属性 + 计算样式 | 同上，另需给组件设 `__scopeId` | 不设 `__scopeId` 就不会打 `data-v-*`，scoped 断言全落空 |
| React | `flushSync` 或等一帧后的 DOM | 点击派发 + `useState` 重渲染 | 打包必须单入口，否则两份 React 导致 hooks 失效 |
| Tailwind | 计算样式 | 只能判效果 | `bg-red-500` 与 `bg-[#ef4444]` 等价，判不了"类名是否恰当" |
| TypeScript | `getPreEmitDiagnostics` 的诊断文本 + 类型等价 | `createProgram` + 缓存 lib + `oldProgram` 增量 | `transpileModule` 对类型错误返回空诊断，只能抓语法错；`noLib:true` 会额外报 10 条 TS2318 噪声，最小要带 `lib.es5`（218 KB） |
| a11y | DOM 属性、标签关联、对比度 | 属性读取 + 对比度计算 | 与 h5-lab 表单章有重叠，需划范围 |
| 动画 | 最终计算值 + 声明的过渡属性 | 读 `transition-*`/`animation-*` 声明，或等 `animationend` | 时间维度与现有 40 ms/1.5 s 的等待策略不兼容 |

### TypeScript 类型断言的三种可行做法（都实测过）

| 做法 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| A. `Equals` 条件类型 | `type Eq<A,B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false` | 最严格的精确等价 | 报错信息不可读；`const s = "abc"` 推字面量类型会误判 |
| B. `checker.isTypeAssignableTo` 双向 | 取两处类型的 Type 对象，双向可赋值即等价 | 可配 `typeToString` 回显"你写成了 X"，推荐做主逻辑 | 需要拿 `TypeChecker` 实例 |
| C. 双向赋值探针 | 追加两句赋值，看诊断条数 | 代码最少，不需要 checker API | 抓不到"多写了属性"；反向探针必须写 `typeof __v` 而不是 `typeof (expr)` |

## 5. 共同硬约束（依赖型演练场必读）

实测的浏览器行为矩阵。这些约束决定了 vendor 怎么打包、判题跑在哪一侧。

| 能力 | `http://` 父页面 | `file://` 父页面 | `sandbox="allow-scripts"` iframe（opaque origin） | `sandbox="allow-scripts allow-same-origin"` iframe |
|---|---|---|---|---|
| `fetch()` 读本地文件 | 可以 | **失败**（Failed to fetch） | 失败 | 可以 |
| `XHR` 读本地文件 | 可以 | **失败**（status 0） | 失败 | 可以 |
| classic `<script src>` 加载本地 js | 可以 | 可以 | **失败**（onerror） | 可以 |
| 内联脚本执行 | 可以 | 可以 | 可以 | 可以 |
| `localStorage` | 可以 | 可以 | **抛 SecurityError** | 可以 |
| 父页面读 iframe 的 DOM / window | — | — | **抛 SecurityError**（必须 postMessage） | 可以（隔离失效） |
| `new Function` / eval | 可以 | 可以 | 可以（但 CSP 不含 `unsafe-eval` 时全废） | 可以 |
| blob / data URL 的 Worker | 可以 | 可以 | 可以（origin 显示 `null`） | 可以 |
| 相对路径的 Worker 脚本 | 可以 | 拒绝 | 拒绝 | 可以 |
| blob worker 内 `importScripts('相对路径')` | 失败 | 失败 | 失败 | 失败 |

由这张表推出的两条打包规则：

1. **依赖库要在构建期打成一个 classic js 的源码字符串包**（例如 `window.__VENDOR={vue:"...",sfc:"..."}`），父页面读出后内联进 `srcdoc`。只有走 `run.bat`（http）时才能直接 `<script src>`。想省掉这层文本包就得放开 `allow-same-origin`，实测那样判题 iframe 能读到父页 `document.title`，隔离没了，不建议。
2. **判题数据只能走 postMessage**。父页面拿不到沙箱 iframe 的 `window`，`localStorage` 在沙箱里也不可用（进度只能记在父页面这一侧）。

其它已踩过的坑：

| 坑 | 现象 | 修法 |
|---|---|---|
| SFC / 用户代码里含 `</script>` | 提前闭合脚本元素，代码被截断 | 注入前 `JSON.stringify` 再把 `<` 转成 `\u003c`（顺带处理 U+2028/2029） |
| SFC 编译产物是 ESM | `SyntaxError: Cannot use import statement outside a module` | 改写 `import {...} from 'vue'` → `const {...} = Vue`（正则**必须带 `/g`**，模板 helper 与用户代码各来一条），`export default` → `return`，再 `new Function('Vue', code)(Vue)` |
| 断言引擎特定报错文案 | 换浏览器就假失败 | 断言 `e.name` 或 `e.message.length > 0` |
| 页面 CSP 含 `script-src` 但不含 `unsafe-eval` | `new Function` 全废 | 本站不加 CSP；文档里写明这个前提 |
| iframe 预览挂载点没插进文档 | 判题 5 秒超时"出错了" | 离屏自测发现不了，必须靠"真在页面上点一次运行"的验收脚本 |

## 6. 各方向技术路线

### 6.1 CSS（第一优先）

引擎工作几乎为零：h5-lab 的 CSS 页签、真渲染预览、`style()` / `has()` / `count()` 断言直接复用。需要补的能力只有两项：

| 新增能力 | 用途 | 实现要点 |
|---|---|---|
| 几何断言辅助（`rect(sel)`、列数、间距） | 布局判题 | `getBoundingClientRect` 取整后比较，容差 ≤ 2px |
| 两阶段断言（改 iframe 宽度后重读） | 响应式、媒体查询、容器查询 | 父页面改 `iframe.style.width`，等 iframe 内 resize 后重读计算值 |

实测可用性（Edge 新版 `CSS.supports` 全部为 true）：`container-type`、`:has()`、`color-mix()`、CSS 嵌套、`oklch`、`@layer`。实测行为：`md:flex-row` 在 1000 px 宽时 `row`、520 px 时 `column`；`@container (min-width:600px)` 随容器宽度同步切换。

建议分册：基础与层叠（选择器、优先级、盒模型、排版、颜色与单位）、布局与现代特性（定位、flex、grid、变量、@layer、容器查询、响应式）。

### 6.2 Vue 3（第二优先）

可教真实写法（`<script setup>` + `template` + `style scoped`），全链路已在 `file://` 跑通。

打包（一次性，产物入库）：

```bash
export HTTPS_PROXY=http://127.0.0.1:7897
curl -sL -o compiler-sfc.esm-browser.js \
  https://cdn.jsdelivr.net/npm/@vue/compiler-sfc@3.5.43/dist/compiler-sfc.esm-browser.js
npx esbuild compiler-sfc.esm-browser.js --bundle --format=iife \
  --global-name=VueSFC --minify --outfile=vue-sfc-compiler.js   # → 803,537 B
```

运行时流程（判题 iframe 内）：

| 步 | 动作 | 备注 |
|---|---|---|
| 1 | `VueSFC.parse(src)` → descriptor | — |
| 2 | `VueSFC.compileScript(descriptor, {id, inlineTemplate:true})` | 产出含 ESM import 的代码 |
| 3 | `VueSFC.compileStyle({source, filename, id, scoped:true})` | 内置 postcss 够用，不必另装 |
| 4 | 改写 import / `export default`，`new Function('Vue', code)(Vue)` | 正则带 `/g` |
| 5 | `comp.__scopeId = 'data-v-xxxx'` | 不设则 scoped 失效 |
| 6 | 注入编译后的 CSS（`<style>` 元素） | — |
| 7 | `Vue.createApp(comp).mount(el)`，`nextTick` 后回传结果 | 判题等待点 |

vendor 体积：168 KB（运行时）+ 804 KB（编译器）= 972 KB 必需；走沙箱隔离再加 990 KB 文本包，约 1.96 MB。替代方案：只在 http（run.bat）下支持 Vue 站，`file://` 直开时降级，可省掉文本包。

### 6.3 React 19（第三优先）

React 19 已移除 UMD，必须自建单入口 bundle：

```bash
export HTTPS_PROXY=http://127.0.0.1:7897
# entry19.js: import * as React from 'react'; import * as ReactDOM from 'react-dom/client';
#             export { React, ReactDOM };
npx esbuild entry19.js --bundle --format=iife --global-name=ReactBundle --minify \
  --define:process.env.NODE_ENV='"production"' \
  --footer:js="var React=ReactBundle.React,ReactDOM=ReactBundle.ReactDOM;" \
  --outfile=react19.iife.min.js     # → 222,496 B
```

| 方案 | 体积 | 每次运行开销 | 取舍 |
|---|---|---|---|
| React 19 IIFE + htm | 222 KB + 1.3 KB | 16–18 ms | 推荐：htm 写模板，属性写 `onClick=${fn}`，组件用 `<${Comp}/>` |
| React 18.3 官方 UMD + htm | 142 KB + 1.3 KB | 7–8 ms | 更小更快，但版本落后一代 |
| 任一 + `@babel/standalone` | +2.98 MB | +170–245 ms | 仅在教材必须呈现真 JSX 语义时；`runtime` 必须用 `classic`（`automatic` 会 emit `import ... from "react/jsx-runtime"`，而 UMD 全局里没有 `jsx`/`jsxs`） |
| esbuild 预编译练习包 | 143 KB / 223 KB | 14 ms，零转译 | 只能覆盖固定题目与参考答案，学习者现敲的 JSX 覆盖不到 |

### 6.4 TypeScript（第四，需差异化）

`type-challenges` 已占住"类型体操 + 在线判题 + 中文题解"赛道。TS 站要活，定位应是类型基础与工程用法（`strict` 下的常见报错怎么读、怎么修、泛型怎么用），不是刷体操题。

判题骨架（`file://` 下编译器放父页面主线程，沙箱 iframe 只跑用户 JS）：

```js
// 页面里两个 classic script：vendor/libs-embed.js（globalThis.LIB_TEXT，3.2 MB）
//                        vendor/typescript.js（9.1 MB，挂 window.ts；ts.sys 为 undefined）
const LIB = new Map(Object.keys(LIB_TEXT).map(k => [k, LIB_TEXT[k]]));
const OPTS = { target: ts.ScriptTarget.ES2020, module: ts.ModuleKind.ESNext,
               strict: true, noEmit: true, skipLibCheck: true, types: [] };
let program = null;
function check(code) {
  const host = {
    getSourceFile: (name, lv) => name === 'main.ts'
      ? ts.createSourceFile(name, code, lv, true)     // 用户文件每次重解析
      : oldSfGet(name, lv),                           // lib 复用缓存
    getDefaultLibFileName: () => 'lib.es2020.full.d.ts',
    writeFile() {}, getCurrentDirectory: () => '', getDirectories: () => [],
    fileExists: n => n === 'main.ts' || LIB.has(base(n)),
    readFile: n => n === 'main.ts' ? code : LIB.get(base(n)),
    getCanonicalFileName: f => f, useCaseSensitiveFileNames: () => true, getNewLine: () => '\n',
  };
  program = ts.createProgram(['main.ts'], OPTS, host, program || undefined);  // 增量
  return ts.getPreEmitDiagnostics(program).map(d => { /* 格式化 TS{code}: {msg} */ });
}
requestIdleCallback(() => check('let __warm: number = 1;'));  // 预热掉首次的 ~270 ms
```

体积合计约 12.3 MB，首次 270 ms、之后每次判题 2–8 ms。不带 lib 会有 10 条假噪声，最小可用 `lib.es5`（218 KB）。

### 6.5 Tailwind（并入 CSS 册）

单文件 282 KB，页内扫描 class 并生成 CSS，实测在沙箱 iframe 里工作正常（`p-4` → `padding-top: 16px`，`bg-red-500` → `oklch(0.637 0.237 25.331)`，`md:` 变体随 iframe 宽度切换）。

判题只能判效果，且颜色断言要按计算出的 `oklch` 写。适合做 CSS 册里的"工具类与设计系统"一章，不适合单独立站。

## 7. 排除项与理由

| 方向 | 为什么排除 |
|---|---|
| Vite / npm / 打包工具 | 需要真的 node 进程，浏览器沙箱里没有 |
| Node / Express / 后端 | 同上；浏览器里跑不了服务端运行时 |
| 浏览器 DevTools / 网络与性能面板 | 无法在页面内重建这套交互 |
| CSS 预处理器（Sass / Less） | 技术可行（5.5 MB / 155 KB），但原生 CSS 已覆盖变量、嵌套、`@layer`，教学收益在下降 |
| Web API 存储类（localStorage / IndexedDB） | 沙箱是 opaque origin，直接用就抛 SecurityError；h5-lab 已验证只能判"代码写法的正确性"，教不了真实读写 |
| Web Worker | blob worker 可建，但相对路径脚本被拒、`importScripts` 也是，判题链路复杂化 |
