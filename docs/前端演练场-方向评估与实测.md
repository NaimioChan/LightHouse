## 4. 判题手段对照

| 方向 | 状态 | 断言读什么 | 关键手段 | 已知坑 |
|---|---|---|---|---|
| CSS | **已交付** | 计算值、几何、结构 | `getComputedStyle`、`getBoundingClientRect`、元素计数、`document.styleSheets` | 断言里的颜色要按实际计算值写；`<style>` 里用 Tailwind 时颜色是 `oklch(...)` 不是 `rgb(...)` |
| CSS 响应式 | **已交付**（练习字段 `widths`） | 同一份代码在不同 iframe 宽度下的计算值 | 父页面改 iframe 宽度 → iframe 内视口变化 → 媒体查询与容器查询即时重估 | 两阶段练习卡的预览要占一整行，否则媒体查询触发不了；第二阶段等状态用 `watch(name)` 等 `__notify(name)` |
| Vue | 未开工 | `nextTick` 之后的 DOM | 挂载后读 DOM、派发事件、再 `nextTick` 读 DOM | 现有 40 ms 静默期不够，判题要等 `nextTick` 或下一帧 |
| Vue SFC | 未开工 | DOM + `data-v-*` 属性 + 计算样式 | 同上，另需给组件设 `__scopeId` | 不设 `__scopeId` 就不会打 `data-v-*`，scoped 断言全落空 |
| React | 未开工 | `flushSync` 或等一帧后的 DOM | 点击派发 + `useState` 重渲染 | 打包必须单入口，否则两份 React 导致 hooks 失效 |
| Tailwind | 未开工；`css-lab` 第 10 章用零依赖工具类覆盖了思路 | 计算样式 | 只能判效果 | `bg-red-500` 与 `bg-[#ef4444]` 等价，判不了"类名是否恰当" |
| TypeScript | **已交付** | `getPreEmitDiagnostics` 的诊断文本 + 类型等价 | `createProgram` + 缓存 lib + `oldProgram` 增量；期望类型用同 Program 的另一份文件比较；产物走 `program.emit` | `transpileModule` 对类型错误返回空诊断，只能抓语法错；`noLib:true` 会额外报 10 条 TS2318 噪声，最小要带 `lib.es5`（218 KB）；等价判定要单独拆 `any` 与 `readonly` |
| a11y | 部分交付（`css-lab` 第 12 章：对比度、可见焦点、禁用与选中态） | DOM 属性、标签关联、对比度 | 属性读取 + 对比度计算 | 与 h5-lab 表单章有重叠，需划范围；ARIA 关联的断言还没设计 |
| 动画 | **已交付但只到声明层**（`css-lab` 第 11 章） | 最终计算值 + 声明的过渡属性 | 读 `transition-*`/`animation-*` 声明 | 时间维度与现有 40 ms/1.5 s 的等待策略不兼容，站里没做「等到动画结束再断言」 |

### TypeScript 类型断言的三种可行做法（都实测过）

| 做法 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| A. `Equals` 条件类型 | `type Eq<A,B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false` | 最严格的精确等价 | 报错信息不可读；`const s = "abc"` 推字面量类型会误判 |
| B. `checker.isTypeAssignableTo` 双向 | 取两处类型的 Type 对象，双向可赋值即等价 | 可配 `typeToString` 回显"你写成了 X"，推荐做主逻辑 | 需要拿 `TypeChecker` 实例 |
| C. 双向赋值探针 | 追加两句赋值，看诊断条数 | 代码最少，不需要 checker API | 抓不到"多写了属性"；反向探针必须写 `typeof __v` 而不是 `typeof (expr)` |

`ts-lab` 采用的是 B（双向可赋值 + `typeToString` 回显），A 与 C 留着做备选。

## 5. 共同硬约束（依赖型演练场必读）

实测的浏览器行为矩阵。这些约束决定了 vendor 怎么打包、判题跑在哪一侧。

| 能力 | `http://` 父页面 | `file://` 父页面 | `sandbox="allow-scripts"` iframe（opaque origin） | `sandbox="allow-scripts allow-same-origin"` iframe |
|---|---|---|---|---|
| `fetch()` 读本地文件 | 可以 | **失败**（Failed to fetch） | 失败 | 可以 |
| `XHR` 读本地文件 | 可以 | **失败**（status 0） | 失败 | 可以 |
| classic `<script src>` 加载本地 js | 可以 | 可以 | **失败**（onerror） | 可以 |
| 内联脚本执行 | 可以 | 可以 | 可以 | 可以 |
| `localStorage` | 可以 | 可以 | **抛 SecurityError** | 可以 |
| 父页面读 iframe 的 DOM / window | — | — | **抛 SecurityError**（必须 postMessage） | 可以（隔离失效） |
| `new Function` / eval | 可以 | 可以 | 可以（但 CSP 不含 `unsafe-eval` 时全废） | 可以 |
| blob / data URL 的 Worker | 可以 | 可以 | 可以（origin 显示 `null`） | 可以 |
| 相对路径的 Worker 脚本 | 可以 | 拒绝 | 拒绝 | 可以 |
| blob worker 内 `importScripts('相对路径')` | 失败 | 失败 | 失败 | 失败 |

由这张表推出的两条打包规则：

1. **依赖库要在构建期打成一个 classic js 的源码字符串包**（例如 `window.__VENDOR={vue:"...",sfc:"..."}`），父页面读出后内联进 `srcdoc`。只有走 `run.bat`（http）时才能直接 `<script src>`。想省掉这层文本包就得放开 `allow-same-origin`，实测那样判题 iframe 能读到父页 `document.title`，隔离没了，不建议。
2. **判题数据只能走 postMessage**。父页面拿不到沙箱 iframe 的 `window`，`localStorage` 在沙箱里也不可用（进度只能记在父页面这一侧）。

`ts-lab` 已经把第 1 条走通一遍：12.3 MB 的编译器与 lib 都以文本形式入库，classic 引入 + 首屏之后懒加载，
`file://` 与 http 双路可用。依赖型的新站可以直接照抄这套，不必重新验证浏览器权限矩阵。

合并进 LightHouse 之后另有一条约束：**入口页读各站进度要求同源**。四座站由根 `serve.py` 一个端口服务，
在线站（GitHub Pages）也同域，所以「已通过 N / M」在两条路上都成立；各站自己的进度键与结构不变，
入口页只读不写。

其它已踩过的坑：

| 坑 | 现象 | 修法 |
|---|---|---|
| SFC / 用户代码里含 `</script>` | 提前闭合脚本元素，代码被截断 | 注入前 `JSON.stringify` 再把 `<` 转成 `\u003c`（顺带处理 U+2028/2029） |
| SFC 编译产物是 ESM | `SyntaxError: Cannot use import statement outside a module` | 改写 `import {...} from 'vue'` → `const {...} = Vue`（正则**必须带 `/g`**，模板 helper 与用户代码各来一条），`export default` → `return`，再 `new Function('Vue', code)(Vue)` |
| 断言引擎特定报错文案 | 换浏览器就假失败 | 断言 `e.name` 或 `e.message.length > 0` |
| 页面 CSP 含 `script-src` 但不含 `unsafe-eval` | `new Function` 全废 | 本站不加 CSP；文档里写明这个前提 |
| iframe 预览挂载点没插进文档 | 判题 5 秒超时"出错了" | 离屏自测发现不了，必须靠"真在页面上点一次运行"的验收脚本 |
| `html, body { height: 100% }`（LightHouse 阶段新增） | 顶栏 sticky 的包含块被限在一屏内：桌面端表现为顶栏滚走，窄屏下抽屉按钮 `getBoundingClientRect().top` 到 −1473px，合成点击打在空中 | `html { height: 100% }` + `body { min-height: 100% }`；断言写成「滚到 1600px 后顶栏 top 仍为 0」 |

### 6.2 TypeScript（已交付：`ts-lab/`，12 章 / 62 练习 / 77 示例）

按原计划的骨架实现：编译器放父页面主线程，沙箱 iframe 只跑要执行的 JS；判题走
`createProgram` + `getPreEmitDiagnostics`，lib 的 SourceFile 跨 Program 复用并传 `oldProgram` 增量。
期望类型用同一个 Program 里的另一份文件比较，等价判定用双向可赋值并单独拆出 `any` 与 `readonly` 两个例外；
要看编译产物时用 `program.emit` 而不是另做一次 transpile。

与原计划的差异只有两处：lib 打进去的是 99 个 `.d.ts`（原估计 100 个），
多了一个计划外的可选文件 `diag-zh.js`（287,554 B 的中文诊断文案，加载失败降级英文）。
体积合计 12.3 MB（编译器 + lib），首次检查 240–270 ms 由 `requestIdleCallback` 预热摊掉，之后每次判题 2–8 ms。

定位也按计划执行：不做类型体操，12 章都是工程用法（推断与注解、对象与函数类型、联合与收窄、数组元组索引签名、
接口与类型别名、泛型、工具类型、类、类型守卫与断言、枚举与运行时的类型、strict 常见报错、异步与 Promise 的类型）。

判题骨架的最终形态（`file://` 下编译器放父页面主线程，沙箱 iframe 只跑用户 JS）：

```js
// 页面里两个 classic script：vendor/libs-embed.js（globalThis.TSLAB_LIB，3.2 MB）
//                        vendor/typescript.js（9.1 MB，挂 window.ts；ts.sys 为 undefined）
const LIB = new Map(Object.keys(TSLAB_LIB).map(k => [k, TSLAB_LIB[k]]));
const OPTS = { target: ts.ScriptTarget.ES2020, module: ts.ModuleKind.ESNext,
               strict: true, noEmit: true, skipLibCheck: true, types: [] };
let program = null;
function check(code) {
  const host = {
    getSourceFile: (name, lv) => name === 'main.ts'
      ? ts.createSourceFile(name, code, lv, true)     // 用户文件每次重解析
      : oldSfGet(name, lv),                           // lib 复用缓存
    getDefaultLibFileName: () => 'lib.es2020.full.d.ts',
    writeFile() {}, getCurrentDirectory: () => '', getDirectories: () => [],
    fileExists: n => n === 'main.ts' || LIB.has(base(n)),
    readFile: n => n === 'main.ts' ? code : LIB.get(base(n)),
    getCanonicalFileName: f => f, useCaseSensitiveFileNames: () => true, getNewLine: () => '\n',
  };
  program = ts.createProgram(['main.ts'], OPTS, host, program || undefined);  // 增量
  return ts.getPreEmitDiagnostics(program).map(d => { /* 格式化 TS{code}: {msg} */ });
}
requestIdleCallback(() => check('let __warm: number = 1;'));  // 预热掉首次的 ~270 ms
```

不带 lib 会有 10 条假噪声，最小可用 `lib.es5`（218 KB）。

### 6.6 视觉糖与动效：能力实测与两处增量（2026-10 补测）

这一节回答两件事：网页上那些「让站看起来贵」的效果，本机能不能用、判题内核读不读得到；以及最划算的两处增量——不新开站，往已有站里加章。
下面的数字都来自本机无头 Edge 154.0.4258 + 判题同构沙箱（`sandbox="allow-scripts"` + srcdoc），http 与 `file://` 双跑结果一致。

#### 6.6.1 四条新的判题原语

四座站现在都没有这四条，而动效类内容全都靠它们判。

| 原语 | 实测 | 能判什么 |
|---|---|---|
| 时间轴可控 | `getAnimations()` → `pause()` → `currentTime = 500`：1 s 线性过渡读回 `left = 50`；600 ms 弹性缓动（`cubic-bezier(.34, 1.56, .64, 1)`）在 300 ms 读到 `matrix(1.0437, 0, 0, 1.0437, 0, 0)`，过冲都被读出来 | 缓动曲线、入场编排、弹性手感；transition 与 `@keyframes` 都适用 |
| 滚动驱动可判 | `animation-timeline: view()` 拿到 `ViewTimeline`；预览容器 `scrollTop = 320` 时元素 `left = 123.81`，`scrollTop = 520` 时 `left = 201` | 滚动显现、进度条、视差；取代「scroll 事件 + rAF」的老写法 |
| SVG 能变像素 | 内联 SVG 经 `XMLSerializer` 序列化成 data URL → `drawImage` → `getImageData`，不污染，读回 `255, 0, 0, 255`；SVG 自带的 `<style>` 跟着走，页面级 CSS 不跟着走 | 一切以 SVG 画的糖（滤镜、路径描边）都能判像素——这是 DOM 侧唯一的像素后门 |
| 样式表可读 | 沙箱里 `document.styleSheets[i].cssRules[j].cssText` 能累计读到全部规则，包括自己写的 `@media (prefers-reduced-motion: reduce)` | 判「你有没有为减弱动效写分支」这类规范性问题 |

指针事件（实测）：`new PointerEvent('pointermove', {bubbles: true, clientX, clientY})` 会正常进元素与 window 上的监听器（元素内读到本地坐标 25、window 读到 65），事件里改完样式读计算值是 `matrix(1, 0, 0, 1, 17, 0)`、几何位移 17 px，对照组 `transform: none`。所以「鼠标跟随、命中检测」这类练习可以判。

判不了的一条：`:hover`。派发 `mouseover` / `mousemove` 之后 `matches(':hover')` 仍是 false、计算颜色不变——伪类只认真实指针。`:focus-visible` 反而能真触发（`input.focus()` 后 matches 为 true、outline 宽度 4 px），`:checked` / `:disabled` / `:target` / `:has()` 同理。这条与 css-lab 现有的「`:hover` 只判声明」一致，新章要按它设计。

时机上的一个细节：视图过渡的伪元素动画（实测读到 `::view-transition-group(card)`、`::view-transition-old/new(root|card)`）只在过渡进行中可见，等 `finished` 就查不到了，要判必须在过渡期间读。

#### 6.6.2 本机 Edge 的支持面

`CSS.supports` 全为 true 的一批：`backdrop-filter`、`mix-blend-mode`、`background-blend-mode`、`mask-image` + `mask-composite`、`clip-path: path()`、`conic-gradient`、`color-mix()`、`oklch()`、`contrast-color()`、`background-clip: text`、`text-wrap: balance/pretty`、`text-box`、`perspective` + `preserve-3d`、`@property`（`CSS.registerProperty` 注册后计算值可读）、`interpolate-size`、`corner-shape`、`scroll-snap`、`scrollbar-color/width`、`subgrid`、`field-sizing`、`anchor-name` + `position-try`、`overlay`、`animation-composition`、`transition-behavior: allow-discrete`、`@starting-style`、`@scope`、`@view-transition`（跨文档）、`@function`。

这些只是「浏览器支持」，与「判题读不读得到」是两件事，能判的是 6.6.1 那四条。

#### 6.6.3 学习价值排序

| 主题 | 教什么 | 怎么判 | 落点 |
|---|---|---|---|
| 缓动与时间轴编排 | 动画是状态的函数；缓动曲线怎么读；错开延迟的编排 | 暂停 + 定位后读计算值 | css-lab 第 11 章的升级，或独立一章 |
| 滚动驱动动画 | 「滚动位置 → 进度 → 样式」的函数关系 | 滚到指定位置读几何 | css-lab 新章 |
| 混合模式与遮罩 | 合成与图层的心理模型 | 计算值 + 几何 | css-lab 新章 |
| 3D 变换与透视 | 坐标系、矩阵与投影；跟着指针倾斜的卡片 | `matrix3d` + 几何 + 派发 PointerEvent | css-lab 或 js-lab |
| 滤镜链与 SVG 滤镜 | 图像算子思维（`feTurbulence` / `feDisplacementMap` 做噪点、gooey、位移扭曲） | 计算值；要判像素走 6.6.1 的 SVG 后门 | 新章 |
| 视图过渡 | 浏览器把「两套 DOM 快照之间的补间」做成了原语 | 调 `startViewTransition`，过渡期间读伪元素动画 | 新章 |
| 指针交互与命中检测 | 事件坐标、rect 与 DPR 的换算、别在 `pointermove` 里改布局属性 | 派发 PointerEvent 后读计算值 | js-lab 新章 |
| 排版细节 | `text-wrap: balance/pretty`、`text-box`、可变字体字重过渡 | 计算值 + 行数几何 | 并进 css-lab 排版章 |
| 性能与可访问性预算 | 只动 `transform`/`opacity`、`will-change` 的代价、`prefers-reduced-motion`、对比度 | 样式表文本 + 计算值 | css-lab 第 12 章往下做 |

观感高但知识密度低的一组，做成一章「配方手册」就够，每个五到十分钟：玻璃拟态（`backdrop-filter` 一行，难的是它下面得真有内容）、渐变文字与 conic 渐变边框、噪点与纸纹 overlay、多层阴影光晕、超椭圆圆角（`corner-shape: squircle`）、自定义滚动条、滚动吸附、可变字体字重动画。

不建议碰：WebGL / 着色器背景（重，教学收益低）、GSAP / Framer Motion 这类动画库（体积大，还要破「无依赖」铁律，而 WAAPI 已覆盖大部分）、Lottie / GIF 动图（判不了、体积大）、大图视差。

#### 6.6.4 增量一：css-lab 加三章

| 新章 | 内容 | 断言写什么 |
|---|---|---|
| 第 13 章 · 混合模式与遮罩 | `mix-blend-mode`、`mask-image` + `mask-composite`、`clip-path`（含 `path()`） | 计算值 + 几何，沿用 `style` / `rect` / `px` / `has` |
| 第 14 章 · 滚动驱动动画 | `animation-timeline: view()` / `scroll()`、`animation-range`，与「scroll 事件 + rAF」的写法对照 | 新增滚动原语：把预览容器滚到指定位置后重读 |
| 第 15 章 · 滤镜与 SVG 滤镜 | `filter` 链（`blur` / `contrast` / `saturate` / `hue-rotate`）、`feTurbulence` + `feDisplacementMap` 做噪点与 gooey | 计算值；要判「看起来对不对」就用 6.6.1 的 SVG → 像素后门 |

引擎要补两样，都是现有「两阶段断言」的扩展：一个「把动画定位到 t 毫秒后重跑断言」的原语（字段形如 `at: 500`，`widths` 已经开了这个头），一个「滚动后重读」的原语（滚动容器 + 两阶段练习卡那种整行预览可以直接复用）。断言辅助沿用 `rect/px/style/has/eq` 那套，不需要像素读值。

验收照旧：新章各自的 starter 至少挂一条、参考解全过（`verify-content.mjs` + `verify-browser.mjs`），新的等待语义要进自测，窄屏与两阶段预览的整行规则不变。工作量按实测均值 69 行/练习算，3 章 × 4–5 练习约 850–1050 行内容。

风险一处：`animation-timeline` 需要真能滚的容器，而练习卡预览窗默认不滚，第 14 章的卡片要按两阶段那种整行预览来做。

#### 6.6.5 增量二：js-lab 加一章

第 15 章 · 指针交互与动效编排：`PointerEvent` 的坐标与命中检测（`getBoundingClientRect` + `elementFromPoint` + DPR）、用 WAAPI（`element.animate` / `pause` / `currentTime`）做可暂停的编排、多条动画错开延迟的 stagger。

判题走 6.6.1 的指针与时间轴两条原语，引擎不需要新能力——断言在沙箱里直接 `dispatchEvent`，再读计算值与几何即可。这一章与 css-lab 第 14 章共用同一套时间轴原语，先做哪边都能给另一边省事。

#### 6.6.6 关于「毛玻璃一定卡」

本机无头 + 软件渲染下量不出差别：560×120 区域做动画时，纯渐变 31 fps、`backdrop-filter: blur(30px)` 30–31、`filter: blur(12px)` 31、`mix-blend-mode: overlay` 30–31，全被环境天花板压平。只能得到「小区域不必然卡」这个结论，整屏连续重绘的代价要在有 GPU 的真机上另测（见第 10 节）。

两处增量都不引第三方代码、不动任何铁律，总工作量 2000 行上下，比新开一座站便宜得多，而且顺手把「时间轴判题」这个所有动效类内容都要用的原语做出来。建议先做这两处，再决定要不要为「视觉与动效」单开一座站。

## 7. 排除项与理由

| 方向 | 为什么排除 |
|---|---|
| Vite / npm / 打包工具 | 需要真的 node 进程，浏览器沙箱里没有 |
| Node / Express / 后端 | 同上；浏览器里跑不了服务端运行时 |
| 浏览器 DevTools / 网络与性能面板 | 无法在页面内重建这套交互 |
| CSS 预处理器（Sass / Less） | 技术可行（5.5 MB / 155 KB），但原生 CSS 已覆盖变量、嵌套、`@layer`，教学收益在下降 |
| Web API 存储类（localStorage / IndexedDB） | 沙箱是 opaque origin，直接用就抛 SecurityError；h5-lab 第 12 章已验证只能判"代码写法的正确性"，教不了真实读写 |
| Web Worker | blob worker 可建，但相对路径脚本被拒、`importScripts` 也是，判题链路复杂化 |

需要后端判题的站（Rust 这类）不在这张表里：它们不是"排除"，而是形状不同——内容仍静态、判题走一次网络，
`file://` 这条路走不通。怎么给卡片标出「这座站需要网络才能判题」，见 `docs/03-languages-and-scale.md`。
